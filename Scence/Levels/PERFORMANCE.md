# 边界矩形、返回落点与存档重置

## 编辑方式

第二章主地图和十七个子关卡的 `Terrain/Boundary_*` 是保存在 `.tscn` 内的 `CollisionShape2D + RectangleShape2D`。碰撞沿道路边缘、墙面和地图外边界布置，墙后不可进入的空白区域不再填满。

选中节点，在 Godot 2D 编辑器修改 Position 或 Shape / Size，保存即可。门、陷阱、宝箱、传送区继续独立。游戏不会生成或改写地形碰撞。第一章主地图保留原有手工碰撞。

本次保留所有原有可通行寻路格和脚部余量：18 张地图修改前后可达格集合完全一致。M 路线图压暗背景后显示连通路面，不会把墙后空白误标为可走区域；F3 可检查实体碰撞和寻路区域。

## 数量与性能

从大块填充改成闭合边界后，内部填充面积减少 **88.1%**。因为一个大填充块改成多条边界，形状数由 1956 增至 2637；仍低于最初的 8048 个细碎片段。每图为 79～246 个边界矩形，直线段合并保留，不再逐格生成。

本机以下测量仅为 `geometry.build()` 寻路初始化，包含碰撞读取、栅格遮挡与连通区域构建，不含资源导入、磁盘加载和首帧渲染。边界版约 8～17 ms。

`geometry.gd` 读取已有碰撞，只在各形状包围范围内检查寻路格。敌人出生候选额外限定为当前锁门状态下玩家可达的区域，避免守卫生成在无法进入的门后。

离线制作工具为 `Tools/author_boundary_collisions.py`，它将已保存的填充矩形提取为边界，并备份到 `.godot/boundary_backups`。历史原始碰撞备份在 `.godot/collision_backups`。后续请直接编辑场景，不要运行历史生成脚本覆盖自己的修改。

## 返回落点

两个主场景统一使用 `geometry.safe_spawn()`：候选落点必须位于出生点所在的连通路面，并通过真实角色脚部的物理查询，排除地形、锁门、海洋入口与其他传送区域。返回位置优先靠近刚离开的门，传送安置结束后恢复移动、清零速度和重置镜头平滑。

## 重置存档

在 Esc 暂停菜单或队伍死亡界面选择“重置存档 / 重新开始”。游戏内确认后清除两章进度、角色解锁、物品和海币，恢复菲比 100 生命 / 200 技能，从第一章出生点开始；音量设置保留。

取消不修改存档。主存档及恢复备份都更新为新进度，避免备份重新加载旧解锁。若新存档写入失败，保留当前内存进度并提示失败。自动测试使用 `.godot/reset_smoke.json`，不会重置真实玩家存档。

## 验证

`Tests/spawn_reset_smoke.gd` 验证全部 17 个返回点、真实移动、错误候选位置修复、取消/确认重置、恢复备份及死亡后重置。两章通关、编辑器保存碰撞变更、背包和死亡流程测试均已回归。
