# 程序目录内的数据保存

游戏自己的进度、音量设置、备份和运行日志统一保存在 `Data` 文件夹。

- **Godot编辑器或源码运行**：`project.godot` 所在目录下的 `Data`，不会写到Godot引擎安装目录。
- **导出后的游戏**：游戏EXE同级的 `Data`。从快捷方式或其他工作目录启动也以EXE位置为准。

```text
游戏目录/
├─ 游戏.exe                         # 源码运行时为 project.godot
└─ Data/
   ├─ Saves/
   │  ├─ campaign_v1.json           # 当前进度
   │  ├─ campaign_v1.json.bak       # 上一次保存/恢复备份
   │  └─ campaign_v1.json.tmp       # 写入期间的临时文件
   ├─ Settings/
   │  └─ audio_settings.cfg         # 音量设置
   ├─ Backups/                      # 迁入的历史手工备份
   ├─ Logs/
   │  ├─ game.log                   # 当前运行日志
   │  └─ game.previous.log          # 上次运行日志
   ├─ migration_v1.json             # 一次性迁移记录
   └─ .gdignore                     # 不作为游戏资源导入
```

## 旧存档迁移

首次创建Data时，会从旧的Godot用户数据目录读取并复制游戏进度、`.bak`备份、音量配置和命名的历史备份。旧文件不会被删除或写入，迁移后的游戏只读写Data。

Data中已有主存档或恢复备份时，旧系统目录中的进度不会覆盖它；音量配置也遵循已有文件优先。迁移完成后写入记录，后续启动不会反复导入旧进度。游戏内“重置存档”仍从1级重开，不会因此恢复系统目录中的旧进度。

搬移游戏时，把整个Data文件夹一并带走即可保留进度和音量。制作发布包时不要包含开发者自己的Data；`.gitignore`和`.gdignore`已排除该目录。

若程序目录不可写，游戏会明确提示错误，不会悄悄改存到系统目录。请选择当前用户可写入的游戏文件夹。

## 实现与验证

- `Scence/data_storage.gd`：最先启动，统一路径、目录创建、迁移和失败提示。
- `Scence/campaign.gd`：通过Storage获取路径，沿用临时文件替换和`.bak`恢复。
- `Scence/global.gd`：音量配置改用Storage路径。
- `Scence/portable_logger.gd`：捕获启动完成后的运行输出，保留上一份日志；每次运行日志上限约2MiB。
- `project.godot`：同时关闭默认系统目录文件日志及桌面平台`.pc`覆盖开关，改用上述日志组件。开发者显式传入的`--log-file`仍由Godot命令行控制。
- `Tests/portable_storage.gd`：路径选择、迁移、覆盖保护、备份、音量、日志、不可写目录测试。
